# Repository Audit — 2026-08-14

This audit compares `docs/ROADMAP.md` against the code that actually boots. It supersedes the
status vocabulary in that file wherever the two disagree.

Method: every claim below was verified by reading the registration path (`includes/Plugin.php`),
the declaring source, and the render path. A capability is only called implemented when it is
declared **and** reachable from a renderer or an enqueue.

## Headline

`docs/ROADMAP.md` substantially understates the product. It reports 82 `MISSING` rows and a
weighted readiness of 44.7%. Verification found that a large share of those rows describe code
that exists, is registered on boot, and renders. The roadmap appears to have been frozen around
the 0.3/0.4 milestone while development continued through the Studio and Core Platform work.

The real risk in this repository is not missing features. It is that the delivered features sit
on a runtime layer that no automated quality gate covers.

## The actual problem: runtime outside the quality gate

The repository contains two parallel worlds.

`src/` is TypeScript. It is covered by `tsc --noEmit`, ESLint, and Jest. It holds **24 files**,
mostly the Container block and a small editor sidebar.

`runtime-src/build/` holds **50 hand-written JavaScript files**. This is where the Studio editor
that users actually operate lives. None of it is typechecked or unit tested.

Within that directory, code quality has regressed over time. The older `standalone-*` layer is
conventionally formatted; the newer `website-builder-*` layer is written as compressed
single-line IIFEs:

| File | Size | Lines | Chars/line |
| --- | --- | --- | --- |
| `website-builder-editor.js` | 58.2 KB | 41 | ~1,454 |
| `website-builder-architecture-v2.js` | 23.8 KB | 28 | ~870 |
| `website-builder-studio.js` | 75.7 KB | 96 | ~807 |
| `standalone-page-settings.js` | 43.0 KB | 812 | ~54 |
| `standalone-visual-editor.js` | 40.3 KB | 504 | ~82 |

`website-builder-studio.js` is the core of the product. At ~800 characters per line, a one-token
change dirties an entire line, so diffs cannot be reviewed meaningfully.

## Accumulated patch layers

Fixes have been applied by adding a layer rather than changing the layer that was wrong. The
naming records this history: `-v2`, `-v3`, `-correction`, `-comprehensive-v3`, `-professional-ux`,
`-stabilization`, `-consistency-guard`, `-visual-parity`, `-rendererparity`.

**PHP.** `includes/Builder/` holds 34 classes. `Plugin::boot()` registers **23 `WebsiteBuilder*`
services unconditionally**, so every layer is live at once. Overlapping responsibilities:

- `WebsiteBuilder` + `WebsiteBuilderPlatform` + `WebsiteBuilderCorePlatform` + `WebsiteBuilderArchitectureV2`
- `WebsiteRenderer` (36.6 KB) + `WebsiteRendererV2` (20.8 KB) — **both** implement tabs, accordion,
  loop, and WooCommerce rendering. Divergence between them is a live correctness risk.
- `WidgetCatalog` + `WidgetArchitectureV2`

**CSS.** 385 `!important` declarations across 32 files in `assets/css/`, concentrated in files whose
names announce that they exist to override earlier files:

| File | `!important` |
| --- | --- |
| `website-builder-ui-correction.css` | 101 |
| `website-builder-structure-v3.css` | 89 |
| `native-preview-suppression.css` | 51 |

A stylesheet that exists only to defeat other stylesheets in the same project means the specificity
contest has been lost. Every future visual change costs more than it should and carries regression
risk.

**Feature flags.** `Support/FeatureFlags.php` defines exactly one flag
(`experimentalEditorTools`). The ten-plus stacked runtime layers cannot be isolated or bisected
when a defect appears.

## Critical: `npm run build` destroyed shipped functionality — FIXED

**Resolved.** The four artifacts are now registered as passthrough entries in
`runtime-src/manifest.json` and stored under `runtime-src/build/`, so
`scripts/build-runtime.mjs` restores them after webpack the same way it already
restored seven other hand-authored runtimes. Passthrough count went from 7 to 13.
`build-runtime.mjs` now also drops any `*.asset.php` the runtime manifest does not
claim, instead of special-casing one filename.

Verified by running `npm run build` twice from a clean tree and confirming
`git status` reports no modification to any of the four. The diagnosis below is
retained because the underlying condition — build outputs whose committed content
does not match their declared source — is what task #6 must not reintroduce.

### Original finding

Running the project's own documented build command on a clean checkout silently replaces four
committed build outputs with smaller ones. The source tree cannot reproduce what the plugin ships.

| Output | Committed | Rebuilt from `src/` | Lost |
| --- | --- | --- | --- |
| `build/preview.js` | 15,809 | 4,730 | 70% |
| `build/standalone-ai-bridge.js` | 18,124 | 10,919 | 40% |
| `build/widget-control-enhancements.js` | 14,122 | 7,897 | 44% |
| `build/container.js` | 16,170 | 9,769 | 40% |

This is not minification variance. `scripts/check-editor-runtime.mjs` requires
`build/widget-control-enhancements.js` to contain `Choose a structured preset`, `aria-pressed`,
`sessionStorage`, `.cc-standalone-left-content`, `observer.disconnect()`, and `pagehide`. **None of
those six strings exist anywhere in `src/standalone/widget-control-enhancements.js`.** The shipped
artifact carries behaviour its source file does not describe, so the artifact was edited directly
and the source was never updated to match.

`scripts/build-runtime.mjs` restores the hand-maintained `runtime-src/build/` outputs after webpack
finishes, which is why that family survives. These four are webpack-owned and have no such
protection.

Consequences:

- `npm run build` is destructive on `main` today. Anyone running it, including CI, ships a
  regression without an error.
- `check:editor-runtime` passes only because the stale artifacts are committed. It flips to failing
  the moment the build runs, which is the inverse of what a build gate should do.
- The reproducible-build and `SHA256SUMS` claims in `docs/RELEASE_ENGINEERING.md` do not hold for
  these four outputs.

Root cause: all four committed artifacts are hand-authored, framework-free IIFEs written against
`wp.*` globals, not webpack output. `build/preview.js` is a hand-transpiled twin of
`src/preview/index.tsx`; the two drifted, and the hand-written side is what ships. They were
declared in `manifest.generated` as webpack-owned, so nothing restored them after a build.

## The quality gate does not pass on `main`

`npm run check:quality` chains 17 sub-checks and is the gate the release process depends on.
Measured against the committed `main` tree at `374ce0d`, before any change in this audit:

| Check | Baseline exit |
| --- | --- |
| `check:hygiene` | 1 |
| `check:studio` | 1 |
| `check:known-defects` | 1 |
| `check:architecture` | 1 |
| `check:production-hardening` | 1 |
| `check:website-builder` | 1 |
| `check:comprehensive-v3` | 0 |

Six of seven fail on a clean checkout. Representative reasons: a missing retired-asset guard for
`build/native-gutenberg-bridge.js`; `HistoryManager.php` registering 4 REST routes while declaring
only 2 permission callbacks; the responsive compiler missing a `tablet` breakpoint tuple.

Two consequences. The gate cannot currently distinguish a regression from the existing baseline,
so it provides no protection. And `docs/KNOWN_LIMITATIONS.md` describes these checks as protecting
release contracts, which overstates what they do while they are red.

The REST permission-callback gap in `HistoryManager.php` should be triaged first; the others are
contract-drift rather than security-relevant.

## Release labelling

The plugin is versioned `1.0.0-rc.1`. `docs/KNOWN_LIMITATIONS.md` states that all eight commercial
gates remain unverified and that no hosted evidence run has executed. Feature coverage is well
ahead of what the roadmap claims, but release-engineering evidence is not. The version label should
follow the evidence, not the feature count.

## Recommended order

1. **Consolidate the runtime.** Move `website-builder-*` into `src/` as TypeScript modules built by
   `wp-scripts`. This is the prerequisite for everything else — it is what makes the `-correction`
   layers unnecessary rather than merely unwanted.
2. **Rebuild the CSS layer** on design tokens and native `@layer`, retiring the override files.
3. **Collapse the duplicate PHP layers**, starting with the two renderers, behind real feature flags.
4. **Close the remaining UX gaps**: onboarding, skeleton loading, command palette, style copy/paste,
   responsive inheritance indicators.
