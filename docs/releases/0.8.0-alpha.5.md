# Cresco Canvas 0.8.0-alpha.5

## Added

- A server-rendered **Filterable Loop** block with progressively enhanced AJAX pagination.
- Load More and Infinite Scroll interaction modes.
- Search and up to three public taxonomy facets.
- Per-loop URL and browser-history synchronization using scoped query-string keys.
- A signed public REST render endpoint that accepts only a server-created query payload and declared filters.
- Request cancellation and sequence checks to prevent stale AJAX responses from replacing newer results.
- No-JavaScript GET filtering and pagination fallbacks.
- WooCommerce query presets for newest, featured, on-sale, in-stock, best-selling, and top-rated products.
- A conservative anonymous request rate limit.
- Checked-in editor and frontend runtimes with responsive filter, result-grid, pagination, loading, error, Load More, and Infinite Scroll states.
- Regression test source for signatures, filter allow-lists, interaction modes, WooCommerce preset names, instance IDs, template restrictions, and bounded payloads.

## REST API

- `POST /wp-json/cresco-canvas/v1/dynamic/interactive-query`

The endpoint is public because it serves frontend visitors. Every request must include a valid HMAC signature for the exact server-created payload. Changing query arguments or block markup invalidates the signature.

## Security and performance

- Public requests may change only search text, declared taxonomy facets, and the bounded page number.
- Query arguments, block markup, WooCommerce preset, post type, item count, and static constraints are covered by the signature.
- Templates are restricted to Core and Cresco blocks and reject executable, third-party, and recursive query block types.
- Query bounds from Advanced Loop remain enforced: public post types, published posts, maximum 24 items, maximum page 999, bounded meta/tax clauses, and no arbitrary SQL.
- Facet taxonomies must exist and be assigned to the configured post type.
- Taxonomy terms are normalized and limited to 24 values per declared facet.
- Search text is limited to 100 characters.
- Public AJAX requests are limited to 120 requests per minute per hashed client address.
- Frontend requests use `AbortController` when available and ignore stale response sequences.

## Progressive enhancement

- With JavaScript, filters update results without reloading the document.
- AJAX mode replaces the current result page.
- Load More and Infinite Scroll append the next result page.
- URL synchronization stores scoped search, facet, and page state and restores it on browser back/forward navigation.
- Without JavaScript, the filter form submits with GET and standard pagination links remain available.

## Known limitations

- Facets currently provide taxonomy selectors but do not calculate live per-option result counts.
- Runtime meta facets, range sliders, active-filter chips, and dependent facet counts are not included.
- Multiple identical Filterable Loops on one page should use unique Instance IDs to prevent URL-key collisions.
- The on-sale WooCommerce preset uses the bounded list returned by WooCommerce and may not preserve an independent static include-ID ordering.
- Dedicated image, gallery, relationship, and nested repeater sub-field bindings inside Repeater/Flexible rows remain future work.
- The checked-in runtimes have not been reproduced from the TypeScript build pipeline because the repository dependency lock/build environment remains unavailable.
- Hosted CI, WordPress/ACF/WooCommerce runtime, accessibility, RTL, multisite, browser, security, and performance verification are not yet available for the current `main` head.
- This is an alpha source/runtime candidate, not a production-verified stable release.
