# Cresco Canvas 1.0.0-rc.1

`1.0.0-rc.1` is a release candidate, not a stable commercial release.

## Current editor architecture

Pages with a saved Cresco document use **Cresco Session v1** as the visual document source of truth. The standalone Cresco editor owns Canvas, Inspector, Structure, responsive preview, undo/redo, History, AI import, and Update for that Session. WordPress remains the host for authentication, permissions, media, Page records, routing, REST, preview URLs, and frontend delivery. User-authored `post_content` is preserved as a fallback.

Primary standalone runtime surfaces include:

- `build/standalone-visual-editor.js`;
- `build/standalone-inspector-v2.js`;
- `build/standalone-ui-v3.js`;
- `build/standalone-page-settings.js`;
- `build/standalone-history.js`;
- `build/global-config-import.js`;
- `build/viewport-shell.js`.

The repository also contains older/native WordPress editor runtimes that remain part of the product tree where still loaded by existing services. Their presence must not be interpreted as making Gutenberg the current Cresco Session document authority.

## Release-engineering hardening

The `commercial/release-quality` line introduces release infrastructure for:

- authoritative ownership of historically hand-maintained `build/` runtimes through `runtime-src/`;
- clean deletion and reconstruction of the complete production `build/` runtime;
- typecheck, JS/CSS/Markdown lint, unit tests, PHPUnit, PHPCS, runtime/version checks, and dependency audits;
- deterministic, strict-allowlist versioned ZIP packaging;
- `SHA256SUMS`, file-level SPDX inventory, and unsigned provenance metadata;
- two-clean-checkout reproducibility comparison;
- WordPress minimum/latest-minus-one/latest plus PHP 8.1–8.4 coverage;
- Chromium, Firefox, WebKit, block-theme, classic-theme, ACF, WooCommerce, and multisite smoke;
- automated axe checks and 50/200/500-node performance measurements;
- exact release-ZIP clean-install smoke;
- pinned historical upgrade smoke from `0.9.0-rc.1`.

These are **gate definitions** until they execute successfully against the exact commit/artifact. `NOT RUN`, `SKIPPED`, and infrastructure/startup failure are not passes.

## Stable-release blockers

Stable `1.0.0` remains blocked until all P0 items in `docs/COMMERCIAL_HARDENING.md` and `docs/RELEASE_CHECKLIST.md` have objective evidence. In particular, the exact release ZIP must pass clean installation and upgrade, automated matrices must pass, security review must complete, and manual accessibility/Edge/cache/optimization checks must be recorded.

The version must remain `1.0.0-rc.1` until that evidence exists.
