# Cresco Canvas 1.0.0-rc.1

## Four-stage editor hardening

This release candidate now uses one Cresco editor foundation instead of coordinating several independent Gutenberg sidebars. Gutenberg remains the document, save, revision, undo, and block-serialization engine; Cresco owns the visual workflow exposed to the user.

### Stage 1 — Stable data and drag-drop

- `build/editor-foundation.js` centralizes block-editor selectors, dispatchers, root identifiers, template locks, insertion permission checks, diagnostics, shared responsive state, and accessibility announcements.
- Elements click insertion and canvas drag insertion use the same factory registry and the same exact `insertBlocks` location.
- Existing widgets use the same validated move controller in Visual Canvas and Structure.
- The previous insert-then-move flow is no longer the primary path, reducing incorrect placement and duplicate undo history.
- Visual Canvas includes a persistent Native Controls switch and a temporary Alt-key fallback.
- A Cresco runtime error disables Visual Canvas instead of hiding the Gutenberg recovery path.

### Stage 2 — One left application shell

- `build/editor-app-shell.js` provides one resizable `Widgets / Edit / Global` panel.
- `build/editor.js` registers Widgets and Global as application views instead of creating another PluginSidebar.
- `build/widget-inspector-persistent.js` registers the Edit view in the same shell.
- Selecting a widget routes to Edit without activating a Gutenberg complementary area.
- The shell includes an error boundary, close/reopen flow, width persistence, visual/native status, and responsive-device status.
- Legacy Hub, workspace-layout, compatibility router, and PluginSidebar inspector runtimes are excluded from the release archive.

### Stage 3 — Responsive and capability-driven editing

- Wide is the base style; Desktop, Laptop, Tablet, and Mobile overrides are stored under `metadata.crescoStyle.responsive`.
- `StyleEngine` schema version 2 sanitizes and compiles responsive overrides for the agreed ranges:
  - Mobile: `0–767px`
  - Tablet: `768–1024px`
  - Laptop: `1025–1439px`
  - Desktop: `1440–1919px`
  - Widescreen: `>=1920px`
- Editor and frontend use the same responsive properties and breakpoint settings.
- Viewport toolbar and Inspector device selection share one state.
- Inspector controls now include specific editing for Cresco Container, Image, Gallery, Button/link fields, Heading, and Spacer, plus shared size, spacing, color, typography, effects, positioning, visibility, anchor, and class controls.
- Structure now supports search, expand/collapse all, keyboard tree navigation, rename, lock/unlock, duplicate, delete, and drag reorder through the shared controller.

### Stage 4 — Release hardening

- `scripts/check-editor-runtime.mjs` checks the syntax of all checked-in editor runtimes and verifies enqueue/package gates.
- CI runs the editor-runtime gate before build, compatibility, and E2E jobs.
- The release archive must contain Foundation, App Shell, Visual Canvas, Structure enhancements, and viewport bridge files.
- CI rejects archives that include the former Hub or legacy Widget Inspector runtime.
- Playwright covers app-shell mounting, selection-to-Edit routing, shared Elements insertion, Structure synchronization, and Native Controls fallback.
- PHPUnit covers responsive CSS compilation and rejection of unsafe responsive values.

## Compatibility strategy

Cresco does not rewrite WordPress core files and does not replace block serialization. Native attributes remain the preferred storage when Gutenberg supports the capability. `metadata.crescoStyle` is reserved for cross-block responsive, effect, and positioning controls that are not consistently available through core block attributes.

Disabling Cresco leaves native block content available. Native Controls mode restores Gutenberg block toolbar and appenders when a third-party block needs a control Cresco does not yet expose.

## Release status

All four hardening stages are implemented at source, checked-in runtime, packaging-definition, and automated-test-definition level. This statement does not mean the current head has passed hosted CI or a real WordPress/XAMPP session. Stable `1.0.0` remains blocked until PHP lint, JavaScript/CSS lint, unit tests, Playwright, Plugin Check, WordPress compatibility matrices, package reproducibility, browser checks, and direct save/reload/undo/drag-drop verification are green on the final commit.
